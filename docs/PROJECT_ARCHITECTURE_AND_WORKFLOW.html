KnowledgeOps AI

Project overview, architecture, code relationships, and process workflow

Purpose. A permission-aware knowledge assistant with document ingestion, grounded question answering, and separate Jira and threat-analysis workspaces.

System boundary. React/Vite browser app → FastAPI API → identity, retrieval, storage, and configured AI services. Keycloak, MongoDB Atlas, Ollama (or explicitly configured hosted models), and Jira Cloud are external services.

Typical chat path: user question → frontend API call → token and capability checks → moderation and routing → scope-filtered retrieval → answer with source citations → audit metadata → UI.

Detailed breakdown 1: UI, identity, and API entry

Frontend: user interaction

frontend/src/app/App.tsx initializes OIDC callback handling, loads the authenticated user, and selects app views.

frontend/src/features/chat/ChatPanel.tsx collects the question, sets loading/error state, calls the chat API, and renders answer plus citations.

frontend/src/api/chat.ts serializes question and retrieval mode to POST /api/v1/chat and maps the response.

frontend/src/api/http.ts adds the OIDC bearer token before calling fetch.

Identity: establish trusted user context

frontend/src/api/oidc.ts configures oidc-client-ts for authorization-code flow with PKCE and handles redirects.

Keycloak authenticates the person and issues a signed token containing identity and group claims.

backend/app/core/auth.py validates signature, issuer, audience, expiry, and required claims; it maps configured groups to allowlisted capabilities.

backend/app/core/permissions.py checks capabilities and derives data scopes. The backend trusts verified claims and server configuration, not UI role values.

API boundary and request lifecycle

  1. backend/app/main.py loads environment settings, configures CORS and request IDs, and mounts the versioned API router.
  2. backend/app/api/v1/router.py connects chat, documents, Jira, threat scans, security alerts, audit, status, and observability routes.
  3. backend/app/api/v1/chat.py:chat() accepts validated input, requires chat:ask, moderates input, calls routing/orchestration, moderates output, audits metadata, and builds ChatResponse.
Connection: UI state and identity flow through a bearer-authenticated HTTP request. The API converts that token into a trusted backend user before any protected operation.

Key files: App.tsx → oidc.ts → http.ts → chat.ts → main.py → router.py → chat.py → auth.py / permissions.py.

Detailed breakdown 2: chat orchestration, retrieval, and LLM

File / componentImportant functionsRole and relationship
backend/app/orchestration/routing.py_classify_intent(), route_question()Classifies a question as knowledge, analytical, workflow, or unsupported using deterministic rules. It returns intent, component, required scope, and clarification state.
backend/app/orchestration/service.pyorchestrate_request(), citation helpersEnforces requested scope; sends knowledge questions to the index; returns planned responses for unsupported or unavailable actions. Chat does not perform Jira writes or threat response.
backend/app/knowledge/index.pyget_knowledge_index()Loads fictional seed corpus and stored document chunks; selects Atlas, Qdrant, or local index from configuration.
backend/app/knowledge/mongodb_index.pyMongoAtlasKnowledgeIndex.search() and embedding/index helpersCreates query embeddings, searches Atlas Vector Search with access-scope filter, combines with lexical ranking, and returns ranked chunks.
backend/app/knowledge/retrieval.pyLocalKnowledgeIndex.search(), reciprocal_rank_fusion()Provides local keyword/vector-like ranking and hybrid rank fusion. Candidate chunks are restricted to the authenticated user's allowed scopes.
backend/app/knowledge/generation.pygenerate_grounded_answer()Returns an abstention if no evidence exists; otherwise builds a grounded response from retrieved chunks and configured generation backend.
backend/app/knowledge/ai_providers.pycreate_embeddings(), create_chat_model()Connects LangChain interfaces to Ollama, or configured Mistral/Groq integrations. Hosted providers require synthetic-data configuration.
backend/app/moderation/guardrails.pyInput, retrieval, and output checksChecks questions and retrieved text for unsafe or injected instructions, then checks answer output before it leaves the API.
LLM relationship: retrieval chooses the evidence first; only those chunks are passed to answer generation. The prompt treats evidence as untrusted data and asks the model to answer only from it. With no evidence, generation is skipped and the app abstains.

Chat answer sequence

chat() → route_question() → orchestrate_request() → index.search(question, user_scopes) → retrieved-text inspection → generate_grounded_answer() → output moderation → citations and response.

Detailed breakdown 3: ingestion, persistence, and connected services

Document ingestion

backend/app/api/v1/knowledge_documents.py:ingest_knowledge_document() is the upload entry. It checks knowledge:manage, file size/type, duplicate content, and ingestion configuration.

Format handlers in pdf_ingestion.py, office_ingestion.py, and text_ingestion.py extract sections and links. Security preflight and extracted-text scanning run before indexing. ingestion.py converts corpus text into chunks with access scope and source metadata.

On success the repository stores document metadata and chunks; chunk embeddings support vector retrieval. Original upload bytes are not retained.

MongoDB Atlas

backend/app/storage/mongodb_knowledge.py stores document and chunk records in separate collections, enforces uniqueness by content hash, and creates supporting indexes.

backend/app/knowledge/mongodb_index.py handles vector indexing and retrieval. Each chunk carries scope metadata so search can filter results server-side.

Runtime configuration supplies connection URI, database, collection names, vector index, embedding provider, and ingestion enablement.

Jira Cloud

The Jira UI calls dedicated routes under backend/app/api/v1/jira.py; integrations/jira_cloud.py talks to Jira REST API using backend-only credentials.

Reads require jira:read. Writes require jira:approve and explicit confirmation. Jira is a separate feature lane, not an action performed by chat.

Threat analysis and alerts

backend/app/api/v1/threat_scans.py exposes authorized scans. threat_detection/ inspects submitted references or text with local rules; it does not execute submitted files or fetch scanned URLs.

Findings may create redacted alerts. Security analysts can review them; optional n8n notifications are separate from automated remediation.

Governance and observability

backend/app/storage/audit.py persists audit events. Chat audit metadata captures route, outcome, and source count rather than question or answer text. Request IDs and metrics are added in main.py; audit routes require authorization.

End state: the user sees an answer with source references, a safe abstention, a clarification, or an access-denied response. Each request is stateless; chat text is not stored as conversation history. Jira writes and threat-response workflows follow separate UI/API flows with their own permissions and confirmations.

Presentation close: “The UI gathers the request, identity establishes who may ask and what they may see, the backend routes and checks it, retrieval supplies permitted evidence, the AI drafts a grounded answer, and governance controls access and traceability.”
